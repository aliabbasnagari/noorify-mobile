# Noorify - Build & Development Guide

Noorify's mobile/desktop client is a Flutter app. This guide covers getting the
source running, building release artifacts, testing, and troubleshooting —
there is no native Android/NDK toolchain, APK decompilation, or DEX-level work
involved; Flutter's own tooling handles all of that under the hood.

## 1. Prerequisites

| Requirement | Version | Notes |
|---|---|---|
| Flutter SDK | `>=3.41.0` | Pinned in `pubspec.yaml` (`environment.flutter`) |
| Dart SDK | `>=3.4.0 <4.0.0` | Bundled with the matching Flutter SDK |
| Android Studio / Android SDK | Latest stable | Required to build/run the Android target |
| Xcode | Latest stable | Required to build/run the iOS and macOS targets (macOS host only) |
| CocoaPods | Latest stable | Required for iOS/macOS dependency linking |
| Visual Studio (Desktop C++ workload) | Latest stable | Required to build the Windows target |
| A Subsonic/OpenSubsonic server | — | Needed to actually log in and use the app while developing |

Check your environment at any time with:

```bash
flutter doctor
```

The `android/`, `ios/`, `macos/`, `windows/`, `linux/` and `web/` folders are
the standard Flutter per-platform "embedder" projects generated by `flutter
create`. You rarely edit inside them directly — Flutter's build commands
drive them — except for platform configuration (app id, permissions, icons,
signing).

## 3. Getting Started

```bash
cd ui-mobile

# Fetch dependencies
flutter pub get

# List available devices/simulators/emulators
flutter devices

# Run on a connected device or simulator (hot reload enabled)
flutter run

# Run on a specific device
flutter run -d <device-id>

# Run the desktop target directly
flutter run -d windows   # or: macos / linux
```

While `flutter run` is active, press `r` for hot reload, `R` for hot restart,
and `q` to quit.

## 4. pubspec.yaml Overview

| Field | Value |
|---|---|
| `name` | `noorify` |
| `version` | `0.1.0+1` (`<version>+<build number>`) |
| `environment.sdk` | `>=3.4.0 <4.0.0` |
| `environment.flutter` | `>=3.41.0` |

Key dependencies:

| Package | Purpose |
|---|---|
| `provider` | App state management (`ChangeNotifier` controllers) |
| `http` | Subsonic/OpenSubsonic REST calls, file downloads |
| `crypto` | MD5 token auth for the Subsonic API |
| `just_audio` | Cross-platform audio playback engine |
| `audio_service` | OS media session / lock-screen, notification & Android Auto controls (`PlayerController` is its `AudioHandler`) |
| `drift` / `drift_flutter` | Local SQLite database backing the library sync cache |
| `cached_network_image` | Cover art loading and disk caching |
| `flutter_secure_storage` | Storing server credentials |
| `rxdart` | Stream composition helpers |
| `shared_preferences` | Lightweight local settings persistence |
| `path_provider` | Resolving app-support/download directories |

Dev dependencies: `flutter_test`, `flutter_lints` (see `analysis_options.yaml`,
which includes `package:flutter_lints/flutter.yaml` plus `prefer_single_quotes`
and `avoid_print`), plus `drift_dev` + `build_runner` (code generation, below)
and `sqlite3` (only used to back an in-memory database in tests).

Model (de)serialization in `lib/models/` is still hand-written
`toJson`/`fromJson` — no `freezed`/`json_serializable`. The **one** place this
project does use code generation is the local database: `drift_dev` +
`build_runner` generate `lib/data/local/app_database.g.dart` from the table
definitions in `app_database.dart`. Regenerate it after changing a table:

```bash
dart run build_runner build
# or, to watch for changes while editing:
dart run build_runner watch
```

## 5. Building Release Artifacts

### 5.1 Android

```bash
# Android App Bundle (preferred for Play Store / most distribution)
flutter build appbundle

# Universal or split APKs
flutter build apk
flutter build apk --split-per-abi
```

Output lands under `build/app/outputs/`.

**Signing:** `android/app/build.gradle.kts` currently signs release builds
with the debug keystore (`signingConfig = signingConfigs.getByName("debug")`)
so that `flutter run --release` and local release builds work out of the box.
Before shipping a real release, replace this with your own upload keystore:

1. Generate a keystore: `keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload`.
2. Create `android/key.properties` with `storePassword`, `keyPassword`,
   `keyAlias`, `storeFile` (keep this file out of version control).
3. Add a `release` `signingConfig` in `android/app/build.gradle.kts` that
   reads from `key.properties` and assign it to `buildTypes.release`.

The Android `applicationId` is `app.noorify.noorify`
(`android/app/build.gradle.kts`); `minSdk`/`targetSdk`/`compileSdk` and the
version code/name are all derived from Flutter's own tooling
(`flutter.minSdkVersion`, etc., and the `version` field in `pubspec.yaml`) —
there is nothing to hand-maintain there.

### 5.2 iOS

```bash
flutter build ios
# or, to produce an .ipa:
flutter build ipa
```

Open `ios/Runner.xcworkspace` in Xcode to manage signing (automatic or manual
provisioning) and to archive/upload to TestFlight/App Store. The bundle
identifier is `app.noorify.noorify` (`ios/Runner.xcodeproj/project.pbxproj`).

### 5.3 macOS

```bash
flutter build macos
```

Signing/notarization is managed the same way as iOS, via
`macos/Runner.xcworkspace` in Xcode.

### 5.4 Windows

```bash
flutter build windows
```

Produces a standalone executable + runtime DLLs under
`build/windows/x64/runner/Release/`.

### 5.5 Linux

```bash
flutter build linux
```

### 5.6 Web

```bash
flutter build web
```

## 6. Testing

```bash
# Run all tests once
flutter test

# Run a single test file
flutter test test/smart_filter_test.dart

# Run tests matching a name
flutter test --plain-name "ReplayGain"
```

Current tests live directly under `test/`:

| File | Covers |
|---|---|
| `audio_settings_test.dart` | Playback settings (ReplayGain, fades, crossfade, EQ) (de)serialization/behavior |
| `smart_filter_test.dart` | Smart playlist rule evaluation |
| `subsonic_client_test.dart` | Subsonic/OpenSubsonic REST client, including the expanded genres/lyrics/bookmarks/radio/similar-top-songs/extensions surface |
| `app_database_test.dart` | The drift local database (round-trip, replace vs. upsert, per-account scoping) against a real in-memory `NativeDatabase` |
| `retry_test.dart` | `withRetry()`'s backoff/give-up behavior |

There are no platform-specific instrumented/UI test suites in the repo today
(no `integration_test/` directory) — add one with the `integration_test`
package if end-to-end device testing is needed later.

**`flutter analyze` and `flutter test` are not a substitute for an actual
build.** Both run against the Dart VM and will happily pass code that fails
to *compile* for a specific target. Concretely: `google_fonts` versions below
8.0.0 use `FontWeight` as a literal key in a top-level `const` map; dart2js
(the web compiler) rejects this at compile time because `FontWeight`'s
`operator ==` isn't "primitive" enough for const-map canonicalization, but
the VM has no such restriction, so `flutter analyze`/`flutter test` see
nothing wrong. The only way to catch this class of bug is an actual
`flutter build <target>` (or `flutter run -d <device>`) for every platform
the app ships on — run at least `flutter build web`, `flutter build apk`
(or `appbundle`), and `flutter build ios`/`macos`/`windows`/`linux` as
applicable after adding or upgrading a dependency, not just before a release.

## 8. Common Build Issues

### 8.1 Flutter/Dart SDK mismatch
```
Error: The current Dart SDK version is X, which does not satisfy ...
Solution: Run `flutter upgrade` (or switch channels with `flutter channel stable`)
          to match the >=3.41.0 Flutter / >=3.4.0 Dart constraint in pubspec.yaml.
```

### 8.2 Stale or missing dependencies
```
Error: Target of URI doesn't exist / package not found
Solution: Run `flutter pub get` (or `flutter clean && flutter pub get`).
```

### 8.3 iOS/macOS CocoaPods issues
```
Error: CocoaPods not installed / pod install failed
Solution: `sudo gem install cocoapods`, then `cd ios && pod install` (or `cd macos && pod install`).
          `flutter clean` first if pods are in a bad state.
```

### 8.4 Android Gradle sync issues
```
Error: Gradle sync failed / could not resolve dependencies
Solution: Ensure Android Studio's Gradle/AGP versions match what the
          `android/` project expects, and that you have a working internet
          connection to google()/mavenCentral().
```

### 8.5 Device not detected
```
Error: No devices found
Solution: `flutter devices` to list; for Android enable USB debugging, for iOS
          trust the host computer and open Xcode once to accept licenses.
```
